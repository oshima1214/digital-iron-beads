# 実機テストの手順と注意事項

iPhone・iPad で、開発中のアプリを **Expo Go**（App Store の無料アプリ）を使って試すための手順です。
前半は「試す人」、後半は「配信する人」向けです。

---

## A. 試す人の手順

### 1. はじめの準備（1回だけ）

1. **Expo のアカウントを作る**：パソコンかスマホのブラウザで expo.dev を開き「Sign up」（無料）。
   作ったら **ユーザー名** を配信担当に伝える（メールアドレスではなくユーザー名）。
2. **招待を承認する**：配信担当から Expo の招待メールが届いたら、
   - ブラウザの **シークレット（プライベート）ウインドウ** を開く
   - expo.dev に **自分のアカウントで** ログインする
   - 招待メールのリンクを、そのウインドウに貼って開き、承認する
   - ほかの人がログインしたままのブラウザで開くと、その人として処理されて、自分はメンバーになれません
3. **Expo Go を入れる**：iPhone / iPad の App Store で「Expo Go」を入れる。
4. **Expo Go にログインする**：Expo Go を開いて、手順 1 と **同じアカウント** でログインする。

### 2. アプリを開く

1. 配信担当から届いた QR コードを、iPhone / iPad の **カメラ** で読む → 「Expo Go で開く」。
2. 2回目からは、Expo Go のプロジェクト一覧からも開けます。

### 3. 新しい版に入れ替える

配信担当から「新しい版を出しました」と連絡が来たら：

1. 画面の下から上にスワイプしてアプリの一覧を出し、**Expo Go を上に払って完全に終了** する。
2. Expo Go を開き、プロジェクトを開き直す。
3. 変わっていないときは、もう一度 1〜2 をくり返す（Expo Go は前に読み込んだ版をしばらく使うことがあります）。

### 4. 確認して報告する

- 確認する項目は `docs/checklists/` の「実機確認リスト」にあります（配信担当から渡されます）。
- 不具合の報告には、次をそろえてください。

```
端末：iPhone 15 / iPad（第10世代） など
iOS：設定 → 一般 → 情報 →「iOS バージョン」
画面：ホーム / 下ごしらえ / ビーズ化 / 編集 / 制作ナビ / 書き出し / 設定
やったこと：（例）編集画面でペンを選び、シートの左端を上から下へなぞった
起きたこと：（例）ホームに戻った
期待したこと：（例）ビーズが塗られる
指 / Apple Pencil：
スクリーンショット・画面収録：あれば添付
```

画面収録は、コントロールセンターの「画面収録」ボタンで撮れます。

## B. 注意事項

### 開けないとき

| 表示 | 原因と対処 |
|---|---|
| There was a problem loading the project / 403 | Expo Go にログインしていない、または招待をまだ承認していない。A-1 の 2〜4 をやり直す |
| We couldn't find this invitation | 招待が無効になっている。配信担当に **ユーザー名で** 招待し直してもらう |
| 開けるが古いまま | A-3 の手順で Expo Go を完全に終了して開き直す |
| Expo Go が「SDK に対応していない」と出る | Expo Go の更新で、このアプリの版（Expo SDK 58）に対応しなくなった。配信担当に連絡する |

### Expo Go では試せないこと

次の項目は、本番に近い形（TestFlight）になってから確かめます。チェックリストにあっても、Expo Go では飛ばしてください。

- アプリのアイコンと起動画面、アプリ名
- AirDrop や「ファイル」アプリから `.beads` ファイルを開いて、このアプリが起動すること

### 作品データ

- 作った作品は **その端末の Expo Go の中だけ** に保存されます。ほかの人や端末とは共有されません。
- **Expo Go を削除すると作品も消えます。** 残したい作品は「書き出し → .beads で共有」で保存しておいてください。
- 試験版なので、新しい版で作品が開けなくなる可能性もゼロではありません。大切な作品は書き出しておいてください。

### 写真・プライバシー

- 写真は端末の中だけで処理され、インターネットには送られません。
- 不具合報告にスクリーンショットを付けるときは、写っている写真（お子さんの顔など）に気をつけてください。

### お子さん・学校で試すとき

- アカウント作成・招待の承認・ログインは、大人がしてください。
- 学校の管理端末では、App Store からアプリを入れられないことがあります。その場合は端末の管理者に相談してください。
- iPad に実物のプレートを置く「制作ナビ」は、画面の明るさを上げると見やすくなります。

### 印刷（型紙）を試すとき

- 印刷の設定で **倍率 100%（実際のサイズ）** を選んでください。「用紙に合わせる」だと大きさがずれます。

## C. 配信する人の手順

### 試す人を増やす

1. expo.dev → 組織 `digital-iron-beads-team` → Members → Invite。
2. **ユーザー名で** 招待する（メールアドレスより確実）。役割は **Developer**。
3. 相手に「A-1 の 2 の手順（シークレットウインドウで承認）」を伝える。

### 新しい版を配信する

パソコンで順に実行します。

```bash
git pull
```

```bash
npm ci
```

```bash
npx eas-cli@latest update --branch preview --environment preview --platform ios --message "変更の説明"
```

配信できたか確かめる：

```bash
npx eas-cli@latest update:list --branch preview
```

一番上に、今つけた説明が出ていれば成功です。
表示された URL（expo.dev の更新ページ）の「Preview」の QR コードを試す人に送ります。

### 配信のときの注意

- 配信した版は、メンバー **全員** に届きます。途中の版を出すと、全員が途中の版で試すことになります。
- `--message` には何を直したかを書いてください。試す人への連絡にも、その内容を書いてください。
- 試す人の端末で版が入れ替わったか確かめる方法は、今はありません（A-3 の手順で開き直してもらう）。
- Expo Go は、新しい Expo SDK が出るとそちらに合わせて更新されます。そうなると SDK 58 のこのアプリは Expo Go で開けなくなることがあります。そのときは SDK を上げるか、TestFlight での配信に切り替えます。
