# デジタル・アイロンビーズ iOS アプリ 設計仕様書

- 作成日: 2026-11-11
- 対象: Google Colab + Gradio 版 V7（`legacy/DigitalIronBeadsV7_colab.py`、ブランチ `legacy/colab-v7`）の Expo による iOS アプリ化と改良
- ゴール: App Store でのリリース

---

## 1. 目的・利用者・前提

### 1.1 目的
画像や文字から、アイロンビーズの図案（ビーズシート）を作成・編集し、**iPad の画面上に実物のプレートを重ねて**、色ごとに案内しながら制作を支援する。

### 1.2 利用者
- 子ども本人（幼児〜小学生）
- 親子（保護者が主に操作）
- 学校・教室・施設（授業・イベント）

### 1.3 決定事項（要件ヒアリング結果）

| 項目 | 決定 |
|---|---|
| 収益化 | **完全無料**。広告・課金・外部 SDK・分析なし |
| App Store カテゴリー | Kids カテゴリー準拠を前提に設計（外部リンク・設定遷移にはペアレンタルゲート） |
| v1.0 の機能範囲 | 既存機能を**全部移植**＋改良（§3） |
| 対応端末 | **iPhone と iPad（ユニバーサル）**。Android は対象外（コードは Expo なので後から追加しやすい） |
| ビーズのパレット | **カワダのパーラービーズ 32色（品番つき）に一本化**。データ構造は複数ブランドに拡張できる形にする |
| プレート | カワダの正方形プレート 29×29穴、穴の間隔 5mm（約145mm角） |
| 保存 | **端末内のみ**（アカウント・通信なし）＋ **`.beads` ファイルの書き出し・読み込み**（AirDrop 対応） |
| 色決定アルゴリズム | **案1：改良した通常の方式**（§5） |
| リリース名義 | **個人**で出し、クレジットに学校名（日本海情報ビジネス専門学校）を記載。学校の許可は取得済みの前提 |
| 見た目 | **iOS 標準のスタイル**（白とグレー基調、アクセントはシステムの青） |
| UI のフォント | **BIZ UDPゴシック**（SIL OFL、アプリに同梱） |
| 商標 | アプリ名・説明文で「パーラービーズ」を前面に出さない。「パーラー対応色番号」など控えめな表記にとどめる |

### 1.4 元のアプリ（V7）からの意図的な変更
- 「元の色」モード（パレットにない色での表示）は**廃止**。代わりに「手持ちの色だけ選ぶ」機能を入れる
- 簡易8色のパレット（2色モード・文字・編集用）は**廃止**し、すべて32色パレットに統一する
- 縁取りは、シートの「設定」ではなく**編集の1操作**とする（後から編集しても自動では追従しない）
- ナビゲーションで1粒ずつチェックする機能は**入れない**

## 3. 機能一覧（v1.0）

### 3.1 既存機能の移植
1. 画像の取り込み、切り抜き（枠をドラッグして指定）
2. 文字から画像を作成（全角は14マス幅、半角は7マス幅。全角2文字・半角4文字までなど、シートのサイズに応じて上限をチェック）
3. ビーズシートの作成：サイズ 13 / 21 / 29 / 58 / 116、色モード（通常・2色）、使うビーズ（基本16色 / 全32色 / 手持ちの色）
4. 編集：セルを選択、範囲選択、色の変更、削除、Undo
5. 特大シート：58×58 はプレート 2×2、**116×116 はプレート 4×4（新規）**
6. 制作ナビ：色ごとに表示
7. 書き出し（PNG）

### 3.2 改良
| # | 機能 | 備考 |
|---|---|---|
| 1 | ピンチズーム・ドラッグで移動 | **iPhone のみ**。iPad ではシートを固定表示 |
| 2 | なぞって塗る・消す | ペンと消しゴムのツール |
| 3 | バケツ塗り | 上下左右につながった同じ色の範囲（背景も含む） |
| 5 | 必要なビーズの数のリスト | 品番・名前・個数。テキストで共有 |
| 6 | 左右反転表示 | 編集・ナビ・書き出しで切り替え可能（データ自体は反転しない） |
| 7 | 完成イメージのプレビュー | アイロン後の質感を表現 |
| 8 | PDF・印刷 | プレート単位のページ＋必要数リスト |
| 9 | 明るさ・コントラストの調整 | 変換の前処理 |
| 10 | Undo/Redo の強化 | 上限200手、Redo を追加 |

### 3.3 追加要望
- **どの画面もスクロールしない**（1画面に収める）
- **一時保存**：シート作成中・編集中・ナビ中の状態を自動保存し、再開できる
- **ナビで前の色に戻る**（「前へ」と、色の一覧からのジャンプ）
- **超特大 116×116**
- **背景をわかりやすく表示する**（§6.4）
- **縁取り**：指定した色・太さ（1〜2マス）でオブジェクトの外側を囲む

## 4. データモデル

シートは画像として持たず、**マスごとのパレット番号の配列**として持つ。個数の集計・ナビ・編集・書き出しは、すべてこの配列から計算する（元のアプリにあった、ピクセルから色を推定し直す方式は廃止）。

```ts
type PaletteId = "perler-32";

interface Bead {
  index: number;        // 1..32（0 は背景のため使わない）
  code: string;         // "5005"
  name: string;         // "あか"
  rgb: [number, number, number];
  group: "basic" | "extended";
}

interface Sheet {
  width: number;        // マス数
  height: number;
  cells: Uint8Array;    // 長さ width*height。0 = 背景（ビーズを置かない）、1..32 = Bead.index
  paletteId: PaletteId;
}

type SheetSize = 13 | 21 | 29 | 58 | 116;

interface ConvertSettings {
  size: SheetSize;
  preset: "illust" | "photo" | "twoColor";
  allowedBeads: number[];        // 使うビーズ
  maxColors: number;             // 2..32
  noise: 0 | 1 | 2;              // ノイズ掃除の強さ
  removeBackground: boolean;
  backgroundTolerance: number;   // 背景推定で許容する色の差（OKLab ΔE）
  lineThreshold: number;         // 輪郭線とみなす割合（初期値 0.25）
  dither: boolean;               // photo のときのみ
  twoColor?: { dark: number; light: number; threshold: number };
}

interface Project {
  id: string;
  name: string;
  createdAt: string;
  updatedAt: string;
  sheet: Sheet;
  source?: {
    imageUri: string;            // アプリ内にコピーした元画像
    crop?: { x: number; y: number; w: number; h: number };
    brightness: number;          // -100..100
    contrast: number;            // -100..100
    text?: { value: string; textBead: number; bgBead: number };
    convert: ConvertSettings;
  };
  nav?: { plateIndex: number; colorIndex: number };   // ナビの再開位置
  formatVersion: 1;
}
```

### 4.1 シートのサイズとプレートの関係
| サイズ | プレートの枚数 | 配置 |
|---|---|---|
| 13 / 21 / 29 | 1枚（29×29） | 13 と 21 はプレートの左上から配置する（元のアプリと同じ） |
| 58 | 4枚（2×2） | 左上、右上、左下、右下の順 |
| 116 | 16枚（4×4） | 行ごとに左から右 |

プレートへの分割は保存せず、`plates(sheet)` で表示するときに計算する。

### 4.2 保存
- 1作品を1フォルダとして保存する：`projects/<id>/project.json`、`source.jpg`、`thumb.png`
- **自動保存**：シートの変更や画面遷移のたびに、500ms 待ってからまとめて保存する。アプリがバックグラウンドに移るときは即時に保存する
- `.beads` ファイル：`project.json` と元画像を zip にまとめたもの（拡張子 `.beads`、UTI は `jp.<開発者>.digitalironbeads.beads`）。読み込むときはスキーマを検証し、`formatVersion` を見て古い形式を変換する

## 5. 画像 → ビーズシートの変換アルゴリズム（案1）

### 5.1 処理の流れ
入力は、切り抜きと明るさ・コントラスト調整が済んだ RGBA 画像。縦横比を保ったまま **1マス＝8×8ピクセル**の作業用解像度に縮小する（116マスなら最大928px）。シートの正方形に収まらない部分は背景にする。

1. **背景を分ける**
   - 透過がある画像：アルファ値が128未満のピクセルを背景にする
   - 透過がない画像（かつ `removeBackground` がオン）：外周のピクセルから、OKLab の色差が `backgroundTolerance` 以内のピクセルをたどって塗りつぶし、背景とする
   - 背景のピクセルが50%を超えるマスは、背景（0）にする
2. **輪郭線を守る**（preset が illust のとき）
   - 明るさ（OKLab の L）が、周り 5×5 の平均より一定以上低く、かつ絶対値でも暗いピクセルを「線」とする
   - 線が `lineThreshold` 以上を占めるマスは、線のピクセルだけで手順3を行う
3. **代表色を決める**：マスの中の背景以外のピクセルを、それぞれ OKLab で一番近い許可済みビーズの色に置き換え、**一番多い色**をそのマスの色にする。同数のときは、マスの平均色に近い方を選ぶ
4. **色を絞る**：使われている色の数が `maxColors` を超える間、使われている数が一番少ない色を、OKLab で一番近い残りの色にまとめる
5. **ノイズを掃除する**：上下左右に同じ色がない孤立したマスを、周り8マスの多数派の色に変える。強さ 1 は1回、2 は2回行う。手順2で線と判定したマスは対象外にする

**2色モード**：手順3の代わりに、マスの代表の明るさ L を `threshold` で分けて、dark / light のビーズを割り当てる（背景の判定は手順1と同じ）。

**写真プリセット**：手順2をオフにする。`dither` がオンのときは、手順3の代わりにマス単位の Floyd–Steinberg 誤差拡散（OKLab で計算）を行う。

### 5.2 性能
- sRGB を各チャンネル5ビット（32,768通り）に分け、一番近いビーズの番号を引く対応表を、許可済みビーズの組み合わせごとに作って使い回す
- 目標：116マスで2秒以内、29マスで0.3秒以内（中位の iPhone 実機で計測）
- スライダーを操作している間は、作業用解像度を1マス＝2×2ピクセルに下げて、すぐに確認用の結果を出す。指を離したら本番の解像度で処理し直す

### 5.3 比較用のテスト環境 `tools/compare`
- 入力：テスト画像のフォルダと、設定の JSON
- 出力：元の画像、**元のアルゴリズムを再現した結果**（マスの平均＋RGB の距離＋V7 の背景判定）、新しいアルゴリズムの結果を並べた HTML。それぞれに色数と粒数も表示する
- テスト画像は `tools/compare/fixtures/` に置く。著作権に配慮し、リポジトリには自作または自由ライセンスの画像だけを入れる

## 6. 画面と操作

### 6.1 画面の流れ
```
ホーム（作品一覧）
 ├ ＋新しく作る → ① 素材選び → ② 下ごしらえ → ③ ビーズ化の設定 → ④ 編集
 ├ 作品 → ④ 編集（続きから）
 ├ 読み込み（.beads を開く・AirDrop で受け取る）
 └ ⚙ 設定（実寸の微調整、パネルの左右、クレジット）
④ 編集 ⇄ ⑤ 制作ナビ
④ / ⑤ → ⑥ 書き出し
```

| 画面 | 内容 |
|---|---|
| ホーム | 作品カードを2列で表示（サムネイル・名前・日付）。下に「＋ 新しく作る」。長押しで名前の変更・複製・削除 |
| ① 素材選び | 写真 / 文字 / 白紙 |
| ② 下ごしらえ | 切り抜きの枠、明るさ・コントラストのスライダー。文字のときは、文字・文字色・背景色を入力する |
| ③ ビーズ化の設定 | 上に変換結果のプレビュー（使用色数・粒数、元画像と比較）。下にサイズ、用途、使うビーズ、色数の上限、ノイズ掃除、背景の自動除去（必要に応じて背景の許容度・2色の指定） |
| ④ 編集 | ツール：ペン、消しゴム、バケツ、選択（タップ・範囲）、縁取り。選択中は「色の変更」「削除」。Undo/Redo、左右反転、完成イメージ、58以上のサイズではミニマップでプレートを切り替え |
| ⑤ 制作ナビ | プレートを選択。「◀ 前へ」「次へ ▶」、今の色（品番・名前・粒数・何色め）、色の一覧から直接ジャンプ、左右反転。**今の色は実際の色の大きな丸、ほかの色は薄いグレーの小さな丸**で表示する。全色が終わったら完成の表示 |
| ⑥ 書き出し | PNG（写真に保存・共有）、PDF・印刷、`.beads`、必要数リスト（テキスト） |

### 6.2 画面配置（スクロールしない）
- 操作パネルの高さは固定し、シートは残りの領域いっぱいに表示する。項目が収まらないときは、スクロールさせずに、セグメントやシートを開く形にして段階的に見せる
- **iPhone（縦向き）**：上にナビゲーションバー、中央にシート、下にパレット1行とツールバー
- **iPad 横向き**：シートが左、パネルが右（設定で左右を入れ替え可能）
- **iPad 縦向き**：**パネルが上、シートが下**（プレートの手前側で誤ってタップしないようにするため）
- パネルとシートは重ならないようにし、作業中にシートの位置は動かさない

### 6.3 iPad の実寸表示
- 機種の ID から、ポイント密度の表を引く（例：iPad mini は 163pt/inch、そのほかの iPad は 132pt/inch。表は `src/platform/physical.ts` で管理）
- 1マス（5mm）のポイント数 = `5 / 25.4 × ptPerInch × 補正係数`
- **補正係数**は、設定の「実寸の微調整」画面で、画面上の定規やプレートの枠を実物に合わせて調整し、保存する。表にない機種のときは、初めて実寸表示するときにこの画面へ誘導する
- iPad の ④ と ⑤ では、シートを実寸で固定表示する（ズーム・移動はしない）
- ⑤ では、シート領域へのタッチを無効にする（プレートを置いたときの誤操作を防ぐ）
- **iPad mini**：横向きでの使用を必須にする。145mm に足りない分は「上半分 / 下半分」を切り替えて表示する
- iPhone では実寸表示は行わない（ズーム可能な通常の表示）

### 6.4 シートの描き方
- **ビーズ**：塗りつぶした丸（マスの98%の大きさ）。白いビーズは灰色の細い輪郭をつける
- **背景**：小さな灰色の点（プレートの突起のイメージ）だけを描く
- **グリッドの線**：細い線。29マスごと（プレートの境界）に太い線
- **完成イメージ**：角の丸い四角形を隙間なく並べ、中央に小さな穴と軽い陰影をつける
- **左右反転**：描くときに x 座標を反転するだけで、データは変えない

### 6.5 ビジュアルスタイル
- iOS 標準のスタイル：背景は `#F2F2F7`、パネルは白、区切り線は `#E5E5EA`、アクセントは `#007AFF`
- フォントは BIZ UDPゴシック（太さ 400 / 700）
- ボタンの大きさは 44pt 以上（子どもでも押しやすいように）
- 表記は漢字の標準的な表記（ペン、消しゴム、バケツ、選択、縁取り）

## 7. 編集の操作の詳細
- **ペン・消しゴム**：なぞった軌跡上のマスを塗る（消しゴムは0にする）。指を離すまでの一連の操作を、Undo の1単位にする
- **iPhone のジェスチャー**：1本指は塗る、2本指はズーム・移動
- **バケツ**：上下左右につながった同じ値の範囲を塗る
- **選択**：タップで1マスずつ選択・解除。範囲モードでは2点を指定するか、ドラッグで矩形を選ぶ。選択中は「色の変更」「削除」「選択の解除」
- **縁取り**：背景以外のマスの外側にある背景マスを、指定した色で太さ分だけ塗る（太さ2は2回くり返す）。1回の操作が Undo の1単位
- **Undo/Redo**：変わったマスの差分 `{index, before, after}[]` を記録する。上限は200手

## 8. エラー処理

| 場面 | 対応 |
|---|---|
| 画像の読み込みに失敗、または形式に非対応 | メッセージを出して ① に戻る |
| 巨大な画像 | 取り込むときに長い辺を2048pxに縮小 |
| `.beads` の破損・未来のバージョン | 検証で読み込みを中止し、理由を表示。古い形式は変換する |
| 保存に失敗 | トーストで通知。データはメモリに保持し、次の自動保存で再試行 |
| 表にない iPad の機種 | 実寸の微調整画面へ誘導 |
| 写真へのアクセスが拒否された | 案内を表示。設定アプリを開く前にペアレンタルゲート（簡単な計算問題） |

## 9. テスト方針
- `src/core` は TDD で開発する（Jest）。対象は、パレットの最近傍色、変換の各段、色の絞り込み、ノイズ掃除、バケツ塗り、縁取り、範囲選択、プレートへの分割、個数集計、Undo/Redo、`.beads` の読み書き・変換、文字のレイアウト、実寸の計算
- 変換は**小さな合成画像**で検証する。例：輪郭が残るか、背景が除かれるか、色数が上限以下になるか、孤立したマスが消えるか
- 画面は Expo の Web 版を Playwright で動かし、主な流れ（作成→編集→ナビ→書き出し）と、iPhone・iPad サイズでスクロールが発生しないことを確認する
- 実機での確認（実寸表示、ジェスチャー、AirDrop、印刷）は、マイルストーンごとにチェックリストを作ってオーナーに依頼する
- CI では、すべての PR で型チェック・lint・Jest を実行する
